# Запись поездок

## Где находится логика

- `BleController.kt`: каждый разобранный пакет телеметрии передаётся напрямую в `telemetrySink`. `StateFlow` остаётся для интерфейса: он может объединять быстрые обновления, поэтому журнал через него не записывается.
- `WheelMonitor.kt`: начало и завершение сессии, единое монотонное начало для GPS и телеметрии, постоянный wall-clock ID поездки, переподключения, контрольная сводка каждые 5 секунд.
- `core/TripRecorder.kt`: дистанция, движение, энергия/рекуперация, максимумы и средняя мощность. Неподвижный счётчик колеса больше не подавляет расчёт по скорости; следующий прирост счётчика сверяется с уже посчитанной оценкой.
- `TrackRecorder.kt` и `core/GpsFix.kt`: GPS с частотой до 1 Гц, точное разрешение, статусы, проверка точности/возраста/времени/скачков. Перезапуск подписки не обнуляет поездку. Координаты используют время самого GPS-замера, а не время доставки callback.
- `WheelService.kt` и `AndroidManifest.xml`: foreground service `connectedDevice|location`. Тип location включается при разрешённой GPS-записи. Activity повторяет повышение типа при возвращении и после выдачи разрешения. При запрете фонового повышения сохраняется сервис BLE.
- `TripJournal.kt`: последовательная очередь файловых операций на `Dispatchers.IO`, отдельные `files/rides/<id>.csv` и `<id>.track`. Каждое дописывание закрывает файл; длинные маршруты и телеметрия не прореживаются. Ошибка записи видна в карточке сессии.
- `TripHistory.kt`: сводки и восстановление незавершённой поездки по контрольной точке, чтение маршрутов, удаление связанных файлов. Старые GPS-треки из preferences читаются как раньше. Новые файлы хранятся вместе с последними 200 поездками.
- `core/TripCsv.kt`: CSV с единицами в заголовке, одна строка на принятый пакет телеметрии. GPS старше 10 секунд не переносится в новые строки. Десятичная точка не зависит от языка телефона.
- `TripDetail.kt`, `TripMap.kt`: статистика, OSM-карта, выбор точки маршрута; только отрисовка карты ограничена 2400 точками. GPX экспортирует весь сохранённый маршрут.
- `MainActivity.kt`, `TripExport.kt`, `res/xml/share_paths.xml`: подготовка CSV/GPX вне UI-потока, настоящие вложения с именем файла и временным разрешением чтения через FileProvider.

## Форматы и показатели

CSV содержит время UTC/от начала сессии, скорость, напряжение, ток, V×A, PWM, заряд, две температуры, pitch/roll, счётчик колеса, дистанцию сессии, запас хода, мощности из протокола и флаги состояния, GPS-координаты/высоту/скорость/время замера. Это собственная схема Ion, а не обещание совместимости с импортерами WheelLog.

GPX 1.1 — XML-файл GPS-маршрута: координаты, высота и UTC-время. Он предназначен для карт/навигации, а не для всех электрических замеров колеса.

Мощность в сводке — электрическая мощность батареи V×A. Средняя — потреблённая энергия / время интервалов с валидной телеметрией, включая остановки. Разрывы BLE дольше 5 секунд не добавляют время/энергию; рекуперация показана отдельно. Старые сводки читаются без новых полей и показывают «—»; восстановить не записанные ранее замеры невозможно.

## Ограничения проверки

Эмулятор и JVM-тесты проверяют хранение, форматы, разрешения на вложения, карту и расчёты. Реальную непрерывность GPS при заблокированном экране и энергосбережении конкретного телефона нужно подтвердить поездкой. Для записи нужны точное местоположение, включённая геолокация и фоновый режим Ion.
